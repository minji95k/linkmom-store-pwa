## 2. Softr 현행 화면 분석

### 2.1 화면 구조
- 상단 App Bar: 햄버거 메뉴, "Linkmom" 로고+타이틀, 우측 프로필 아바타(이니셜 배지)
- 홈 화면: "링크맘 실시간 프로모션 공지" 타이틀 + 통합 검색창("브랜드, 제품명, 컬러 등으로 검색...") + 통계 카드 3종:
  - 신규 업데이트 건 (최근 7일) — 예: 75
  - 프로모션 등록 (전체 건수) — 예: 188
  - 링크맘 행사 공지 (진행중 행사 건수) — 예: 0 (당시 행사 없음)
- 하단: "매장 프로모션" 탭 1개만 존재 (Bottom Nav라기보다 단일 탭). 공지/교육자료 등 별도 메뉴는 **없음**.
- Softr 플랫폼 자체 UI(좌측 하단 뒤로가기 화살표, 공유/새로고침/나침반 아이콘)가 브라우저 chrome처럼 항상 노출됨 → PWA스러운 완전한 UI 통제가 불가능한 상태였음.

### 2.2 프로모션 리스트/검색 화면
- "운영상품" 섹션, 안내문구: "사은품은 월별 공유되는 업체 프로모션이므로 매장 사은품과는 상이할 수 있습니다." (사은품 정보의 출처가 이원화되어 있다는 뜻 — 온라인/공급사 사은품과 매장 자체 사은품이 다를 수 있음을 명시)
- 검색창: "상품 검색..." (placeholder)
- Filter: "업데이트 상품만보기" 토글/버튼 형태의 **NEW** 칩 1개만 존재. 브랜드별 Filter, 카테고리 Filter는 화면상 확인되지 않음(검색으로 대체하는 것으로 추정).
- 상품은 Key-Value 나열형 카드(Table처럼 라벨(민트색)-값(검정) 반복)로 표시됨. Grid/Card 이미지 썸네일은 없음(제품 이미지 없이 텍스트 중심).

### 2.3 상품 카드에 실제로 노출되는 필드 (화면 캡처 기준)
브랜드 → 제품명 → 상품컬러 → 기본 구성품 → 증정 사은품 → 포토후기 → 소비자가 → 기준 판매가 → 매장 프로모션 → 매장 별 운영상황 → 최종 판매가(카드결제 시) → 최종 판매가(현금or계좌이체 시)

이 순서/필드 구성은 Spreadsheet의 컬럼 구성과 거의 1:1로 대응된다 (아래 3장 참조).

### 2.4 NEW 배지 동작 (실측)
- "업데이트 상품만보기" 옆 **NEW** 버튼을 누르면 외곽선이 보라색으로 활성화됨 (검색어 "리안" + NEW 필터 조합 화면 확보).
- 문제점(마스터 프롬프트 §37과 일치): NEW 배지 대상이 매우 넓다 — 실제 Spreadsheet에서도 188개 중 135개(72%) 행에 `NEW` 플래그가 살아있음(§3.5 참조). 즉 "최근 7일"이라는 창이 넓고, 사소한 수정도 NEW로 잡혀 정말 중요한 변경을 찾기 어렵다는 마스터 프롬프트의 문제의식이 데이터로도 확인됨.

### 2.5 계정/인증
- 우측 상단 아바타 클릭 시 Drawer: 이름(김민지), 이메일(네이버 이메일), "계정 설정", "Sign out". Softr 자체 인증(이메일 기반)을 사용 중이며 매장/Role 개념이 UI에 드러나지 않음(즉 현재는 매장별 데이터 분리가 없거나 있어도 노출되지 않음).

### 2.6 기존 장점 (반드시 유지할 것)
1. 본사가 Spreadsheet만 고치면 직원 화면에 반영되는 운영 흐름 — 매우 만족스럽게 검증된 핵심 가치.
2. 통합검색 하나로 브랜드/제품명/컬러를 다 찾을 수 있는 단순함.
3. 상품별 정보 밀도가 높음 (가격 2종, 사은품, 구성품, 후기 혜택, 매장별 예외까지 한 화면에서 확인).
4. 모바일 홈 화면 추가로 앱처럼 사용하는 운용 패턴이 이미 직원들에게 자리잡음.

### 2.7 기존 한계 (개선 대상)
1. NEW 판정이 "수정 여부" 기준이라 신호 대비 잡음이 많음(72% NEW).
2. 공지사항/교육자료 메뉴 자체가 없음 — 신상품 교육, 운영 공지는 다른 채널(카카오톡 등)에 의존 중인 것으로 추정.
3. Push 없음 — 앱을 직접 열어야만 변경을 인지.
4. 매장별 권한 분리가 화면상 보이지 않음 — 전 매장 데이터가 그냥 다 보이는 것으로 추정.
5. 상시/행사 프로모션이 Softr 화면상 하나의 "운영상품" 리스트로만 보임 — 실제로는 아래처럼 원본 데이터가 이미 시트 레벨에서 분리되어 있는데 이를 UI가 활용하지 못하고 있음.
6. Softr 자체 Chrome(공유/새로고침/나침반 바)이 항상 보여 네이티브 앱같은 몰입감이 떨어짐. PWA 미적용.
7. 제품 이미지가 없어 브랜드/컬러명만으로 상품을 특정해야 함(직원 숙련도에 의존).

## 3. Google Spreadsheet 분석

Excel Export본 기준 **2개 Sheet**를 직접 열어 헤더/샘플/타입/결측치/중복을 전수 확인했다.

### 3.1 `[상시 프로모션]` 시트

**목적**: 매장에서 상시 판매 중인 전체 상품의 기본 가격/혜택 정보. 직원이 평소에 조회하는 기본 데이터.

**규모**: 데이터 행 188건 (헤더 제외, `A2:A189`), 18개 실제 데이터 컬럼 (그 뒤 컬럼은 전부 빈 컬럼 — 시트 여백).

**Column 목록 (순서대로)**:

|---|---|---|---|---|
| 1 | 행사 기간 | 문자열 | 0/188 | `"상시"`(179건) / `"8/1~8/31"`, `"9/7~9/30"`(기간限정 할인 9건) — 연도 없이 월/일만 표기 |
| 2 | 브랜드 | 문자열 | 0/188 | 18개 브랜드 (스토케 54, 브라이텍스 21, 뉴나 20 순으로 다수) |
| 3 | 제품명 | 문자열 | 0/188 | 자유 텍스트, 모델명/스펙 포함 |
| 4 | 컬러 | 문자열 | 14/188 | 콤마로 여러 컬러를 한 셀에 나열(`"코튼 베이지, 클래식 토프, ..."`)하거나 `"A + B"` 조합 표기 혼재 |
| 5 | 공지유형 | 문자열 | 173/188 | 거의 비어있음. 값 예: `"기간 할인"`, `"재고 소진"`, `"재고소진"`(띄어쓰기 불일치 데이터품질 이슈) |

**PK 후보 검증**: `브랜드+제품명+컬러` 조합 기준 중복 0건 → 현재는 자연키로 동작하지만, 컬러가 없는 행(14건) 존재 + 콤마로 여러 컬러를 한 셀에 묶는 방식이 혼재하여 **장기적으로 불안정**. → §15 요구사항대로 별도 `product_id` 컬럼 신설 필요 (아래 4장).

### 3.2 `[행사 프로모션]` 시트

**목적**: 한정기간 특별 행사(예: 링크맘 전국행사, 브랜드전)에만 노출되는 별도 상품 목록. 상시 시트와는 완전히 분리된 행/헤더 구조를 가진 독립 시트.

**규모**: 데이터 행 16건, 14개 실제 데이터 컬럼.

**Column 목록**:

| # | 컬럼명 | 결측 | 비고 |
|---|---|---|---|
| 1 | 행사 기간 | 0/16 | **16건 전부 `"8/13~8/26"`** 단일 값 — 이번 Export가 과거 특정 1개 행사(이미 종료된 기간)의 스냅샷임을 의미. 오늘(2026-09-09) 기준 이미 종료된 행사 데이터가 삭제되지 않고 남아있음 → §21 "행사 종료해도 데이터 삭제 안 함" 원칙과 일치하는 실제 운영 사례 |
| 2 | 브랜드 | 0/16 | 9개 브랜드 (미마, 순성, 브라이텍스, 오르빗, 베이비브레짜, 시크, 잉글레시나, 리안, 뉴나) |
| 3 | 제품명 | 0/16 | |
| 4 | 컬러 | 13/16 | 대부분 결측 |
| 5 | 공지유형 | 0/16 | **16건 전부 `"링크맘 행사"`** 고정값 |
| 6 | 소비자가 | 0/16 | 숫자 |
| 7 | 기준 판매가 | 2/16 | 숫자, 결측 허용(할인 전 가격이 없는 경우 존재) |
| 8 | 최종 판매가 (카드결제) | 1/16 | 숫자 |
| 9 | 최종판매가 (현금or계좌이체) | 1/16 | 숫자 |
| 10 | 매장 별 운영 | 0/16 | `"모두 운영"`(15) / `"동백 불가"`(1) |
| 11 | 행사 사은품 | 3/16 | 상시 시트의 "증정사은품"과 다른 컬럼명 — **행사 전용 사은품 필드**로 명확히 구분되어 있음 |
| 12 | 매장 프로모션 | 0/16 | **16건 전부 `"불가"`** — 행사 상품은 매장 자체 추가 할인이 불가하다는 뜻으로 해석됨 (상시 시트는 반대로 대부분 `"가능"`) |
| 13 | 비고 | 4/16 | 한정수량, 지역화폐 사용 가능 여부 등 |
| 14 | 🔐 Softr Record ID | 0/16 | 16개 전부 유일 |

**중요한 구조적 공백 (설계 시 반드시 보완 필요)**:
- ❌ **행사명(캠페인명) 컬럼이 없음** — "링크맘 전국행사"처럼 여러 행사를 구분할 상위 개념이 시트에 없음. 지금은 사실상 시트 1개 = 행사 1개처럼 운영된 것으로 보임.
- ❌ **노출여부(ON/OFF) 컬럼이 없음** — §21/§22가 요구하는 "관리자가 켜고 끄는 노출 스위치"가 현재 시트에는 존재하지 않는다.
- ❌ **정형화된 시작일/종료일 컬럼이 없음** — "행사 기간"이 `"8/13~8/26"` 같은 자유 텍스트이며 연도 표기가 없어 파싱 시 "올해"를 가정해야 하고, 연말~연초에 걸치는 행사는 오파싱 위험이 있음.
- ⚠️ **"수정일" 컬럼 자체가 시트에 없음** — 상시 시트와 달리 행사 시트는 변경 이력을 전혀 추적하지 않음. Change Log/NEW 판정을 위해 Sync 쪽에서 자체적으로 변경 감지를 해야 함(시트의 타임스탬프에 의존 불가).

### 3.3 두 시트 공통 필드 vs 차이 필드

| 공통 필드 (Core 후보) | 상시만 있음 | 행사만 있음 |
|---|---|---|
| 행사 기간, 브랜드, 제품명, 컬러, 공지유형, 소비자가, 기준 판매가, 최종 판매가(카드결제), 최종판매가(현금or계좌이체), 매장 별 운영, 매장프로모션, 비고, Softr Record ID | 기본 구성품, 포토후기, 수정일, NEW, 최근 수정 건수 | 행사 사은품 (증정사은품과 별도 개념) |

→ "사은품"은 상시=`증정사은품`, 행사=`행사 사은품`으로 **컬럼명 자체가 다르다**. DB 설계 시 의미는 동일(gift)하되 출처 컬럼명이 다르므로 Sync 매핑 테이블에서 각각 명시적으로 지정해야 한다(§16 참조).

### 3.4 데이터 품질 이슈 목록 (설계에 반영함)

1. `공지유형` 값에 `"재고 소진"`/`"재고소진"` 같은 **띄어쓰기 불일치**가 실존 → §41의 "minor 수정은 NEW/Push 제외" 원칙이 실제로 필요한 이유가 데이터로 증명됨.
2. `최종 판매가 (카드결제)`와 `최종판매가 (현금or계좌이체)`는 컬럼명 표기가 미묘하게 다름(공백 위치) → Sync 헤더 매핑은 트리밍(trim) + 정확 일치 두 단계로 처리해야 함.
3. `최근 수정 건수` 컬럼은 상품 데이터가 아니라 요약 통계 셀이 섞여 들어간 것으로 보임 → **Sync 시 이 컬럼(및 `NEW`, `수정일`, `Softr Record ID`)은 Dynamic Field 자동수집 대상에서 제외하고, Softr 전용 메타컬럼으로 별도 취급/무시해야 함.**
4. `행사 기간`이 상시 시트에서도 `"상시"`가 아닌 실제 날짜 범위(`"8/1~8/31"`)로 채워진 행이 9건 존재 → 상시 시트 안에도 "기간한정 할인"이 섞여 있다는 뜻. 이는 새로운 `event_campaigns`가 아니라 **상품 자체의 Core 필드 값**(기간限정 판매)으로 처리하면 충분하며, 노출 ON/OFF 같은 별도 캠페인 로직은 필요 없음(행사 프로모션 시트의 캠페인 개념과는 별개).
5. 날짜 범위 표기에 연도가 없음 (`"8/13~8/26"`) → 파싱 시 연도 추론 로직과 담당자 확인이 필요 (연말/연초 경계 케이스는 수동 확인 권장).
6. `컬러` 셀에 여러 컬러가 한 문자열로 뭉쳐 있는 방식과, 컬러별로 행을 나누는 방식이 혼재 → 검색/필터 시 콤마 split 후 배열화 필요.

## 4. Product ID 전략 (실측 데이터 기반 결론)

- 현재 자연키 후보(`브랜드+제품명+컬러`)는 188건/16건 모두 **중복 없음**이 확인되었으나, 컬러 결측·다중값 셀 때문에 장기적으로 불안정.
- `🔐 Softr Record ID`는 상시 188개, 행사 16개 모두 **유일값**이라 이관 매핑 키로는 훌륭하지만, Softr 종속 ID라 §15 원칙(제품명이 아닌, 변경되지 않는 자체 ID) 상 회사 소유의 `product_id`로 승격하기엔 부적합.
- **권장안**: 신규 `product_id` 컬럼을 Spreadsheet에 추가(개발/복제 시트에서 우선 검증)하고, `legacy_softr_record_id`를 참고 컬럼으로 유지. 초기 마이그레이션 시 Softr Record ID를 `product_id` 발급의 시드로 사용(예: 해시 또는 순번 매핑)하되, 이후 신규 상품은 서버가 `product_id`를 채번해 담당자에게 안내하는 흐름을 권장(§15 "안전하게 product_id를 생성할 방식" 요구 충족).

## 5. 매장(Store) 현황

- Spreadsheet 데이터만으로 확인 가능한 매장: **본점(암묵적 기본값), 동백점** — `매장 별 운영` 컬럼에 `"동백 불가"` 예외만 존재하고 그 외에는 전 매장 운영을 의미하는 `"모두 운영"`.
- 마스터 프롬프트 예시(용인본점/용인동백점)와 일치. Store 테이블은 최소 2건으로 시작하되 향후 매장 추가를 기본 가정으로 설계(§50).
